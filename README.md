# 麻将记分 · 中文网页版

打完每局后录入最终点数，整场结束后统一录入祝仪。纯静态网站，适合手机和电脑，用 GitHub Pages 托管。

## 使用

1. 添加一起打牌的成员，再创建三麻或四麻记录。
2. 每局只录最终点数。输入 `250` 代表 25,000 点，最后一人的点数可自动补齐。
3. 打完整场后，在成绩页最下方「整场祝仪」填写各人的净数量。获得填正数，支付填负数。
4. 可修改成绩、查看累计统计、导出 CSV，以及导出/导入 JSON 备份。

默认持有与返还点数都是 25,000；四麻顺位马为 +15 / +5 / −5 / −15；三麻为 +20 / 0 / −20。祝仪每人默认 0，每祝默认 3 PT，可修改。

整场总成绩 = 各局麻将成绩合计 + 整场祝仪净数量 × 每祝 PT。整场祝仪只计入一次，后来补录对局不会重复加入。每 PT 的金额默认 0，修改后按 PT 折算收支；台费可均分或自定义。旧版按局登记的祝仪保留，整场入口只需登记尚未记录过的新增祝仪。

## 本地数据

- 成员、成绩、规则和祝仪存入当前浏览器的 `localStorage`，键为 `mahjong-score-cn-v1`。
- 网站不会将这些记录上传到 GitHub 或其他服务器；GitHub Pages 只提供程序文件。
- 不同设备或浏览器各自保存数据。换设备时导出 JSON，再在新设备导入。
- 清除该网站的浏览器数据会清除记录，因此请保留 JSON 备份。普通版本更新保留本地记录。
- 首次在线打开后缓存程序文件，可离线再次访问。可使用浏览器的「添加到主屏幕」快捷打开。

## 牌谱结算（原生解析）

底部「牌谱结算」进入独立页面 `paipu.html`。本站自行解码雀魂 Protobuf 记录并计算祝仪，不嵌入 mjget，不调用其算分接口。

- 一发、红宝、里宝各 1 祝；红宝和里宝按实际数量累计。荣和只向放铳者收取，自摸向其余各家分别收取。
- 役满每份荣和固定 10 祝；自摸由其余每家各付 5 祝，四麻合计 15 祝。双倍与复合役满按份数叠加，和其他已确认的祝仪合计；累计役满不额外触发役满祝。
- 页面只提供「每祝价值（PT）」和「折算倍率」两个设置，默认分别为 3 与 10。麻将 PT 直接采用官方牌谱 `head.result.players[].total_point / 1000`，已包含雀魂在该牌谱采用的素点与顺位马，不再另设返点或叠加自定义马点。总 PT = 麻将 PT + 净祝数 × 每祝 PT。
- 本机旧牌谱存档和导入备份保留每祝 PT、折算倍率与牌谱记录，旧自定义返点、顺位马与同分规则不再参与牌谱结算。役满规则使用上述固定值。
- 显示多谱累计、各谱结算、逐局计祝来源和支付明细，支持 CSV 及 JSON 备份。
- 支持导入包含元信息及事件的完整原始 JSON，由本页解码后计算；也可导入本站导出的解析备份。支持旧 records 与新版 actions 二进制封装；仅含牌谱 UUID 或头信息而无事件的数据会明确拒绝。
- 独立本地存储键为 `mahjong-paipu-cn-v1`，不读写原手动记分存档。解析结果不会自动写入手动成绩簿；可返回首页录入最后结果。
- 新解码的和牌记录保留役满份数；旧解析备份若缺少官方结算分或役满份数，会保留记录并提示暂不能结算。重新读取同一牌谱可在原位补齐，完整的新解析校验通过后才替换旧记录；不会重复累计，也不会将缺失值填成 0。JSON 及 CSV 均保留官方麻将 PT。

链接下载由公共云端专用账号完成，访客无需登录雀魂或 ChatGPT，不需要授权弹窗。只提交自己要读取的官方分享链接，前端收到原始牌谱后独立解析；结果仍仅保存在各自浏览器。专用账号的邮箱、验证码和登录会话不会传给访客。

专用账号由站点所有者在 `/admin` 管理；管理员操作和个人后台仍要求所有者身份。公共服务设有请求限流和串行读取，繁忙时请稍后重试；未成功的牌谱不会计入结算。可直接使用 [牌谱结算页面](https://diw1.github.io/mahjong-score-cn/paipu.html)，或云端的同一套页面；两个域名各自保存浏览器记录，可用 JSON 备份转移。

已取得的完整原始文件和已保存结果可在本页离线解析、重算。官方元数据、登录与后台接口、WebSocket 和第三方资源均不加入 Service Worker 缓存。

## 开发与部署

无需安装运行依赖。用本地静态服务器预览，不建议直接打开 `file://`：

```powershell
python -m http.server 8873 --bind 127.0.0.1
```

在 `http://127.0.0.1:8873/` 预览；此来源在云桥开发白名单中。本地预览与在线站点分别保存数据。

有 Node.js 时运行计分测试和语法检查：

```powershell
npm test
npm run check
```

发布到 GitHub Pages 时，选择包含 `index.html` 的分支根目录。`.nojekyll` 使静态文件直接发布。`sw.js` 的缓存版本随静态资源版本更新。

本项目按用户指定的日本应用公开界面及指南独立实现，未使用原安装包代码或商标图标。已知计分约定：负数按绝对值五舍六入再恢复符号；取整尾差归头名；全员烧鸟不扣罚；台费默认均分全部登记成员。
